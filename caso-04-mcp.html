Programa 02 · MCP × Figma

La tecnología

¿Qué es un MCP Server?

Definición
MCP
Model Context Protocol · Anthropic, noviembre 2024
Es un intérprete universal: conecta una IA con cualquier sistema y le da el contexto exacto que necesita para trabajar bien. No es magia — es protocolo.
"No es magia. Es contexto. Y contexto es todo."
1
Expone datos de forma ordenada
El MCP serializa Figma y el código en un formato que la IA puede leer con precisión, sin ambigüedad.
2
Estandariza cómo la IA entiende esos datos
En lugar de cada herramienta hablar su propio dialecto, el protocolo define una gramática común entre diseño, desarrollo y AI.
3
Permite que la IA actúe, no solo lea
La IA puede preguntar, leer y ejecutar acciones sobre el sistema. Genera código que usa los mismos componentes y tokens que el diseño.
El salto

¿Por qué en Figma cambia todo?

El MCP Server de Figma no lee una imagen — accede directamente al archivo y entiende el diseño como un modelo estructurado. Cada capa, cada componente, cada token.

◈
Componentes y variantes
La IA conoce exactamente qué componentes existen y cómo se usan, no los reinventa.
⬡
Variables y tokens
Color, tipografía, espaciado — el código generado usa los mismos tokens del Design System.
⊞
Auto Layout = responsive explícito
Las reglas de comportamiento responsive ya están en el diseño. La IA las lee, no las adivina.
⌥
Jerarquía de capas y props
El contexto de estados, condiciones e interacciones viaja intacto desde Figma al código.
El resultado
Código que no es un primer borrador — es el diseño hecho código.
Cuando la IA tiene acceso al archivo estructurado, genera código preciso usando los mismos componentes y tokens del Design System. El dev recibe algo que puede usar, no algo que tiene que reescribir.
"Esto hace que la IA genere código mucho más preciso. Y lo hace usando los mismos componentes y tokens del Design System."

Lo que construí

Nuevo estándar IA-ready para el equipo

La tecnología estaba disponible para todos. Lo que hice fue entenderla a fondo, construir el framework de adopción y formar a 14 personas para que trabajaran de una manera nueva — antes de que el banco lo exigiera.

01
Invertir en las bases
Conectar diseño con código
  • Code Connect: vincular cada componente de Figma con su par en código para que la IA sepa qué usar.
  • Code syntax: definir cómo se deben escribir las variables para web y nativo — un idioma compartido.
02
Estructurar el handoff
Diseñar para que la IA entienda
  • Frames por breakpoint: el comportamiento responsive explícito, no supuesto.
  • Auto Layout siempre: diseño que ya porta sus reglas de flexibilidad.
  • Capas con nombre: cuando no son claros, la IA interpreta mal y genera código incorrecto.
  • Componentes sin detachar: evitar inconsistencias en el código generado.
03
Compartir la intención
Anotar para que la IA no adivine
  • Estados interactivos: qué pasa en click, hover, focus — explícito en el archivo.
  • Estados condicionales: cuándo algo cambia según una acción o condición.
  • Contenido dinámico: aclarar qué datos vienen de fuentes externas.
Programa 03 · Research Agent

De la dependencia al ciclo autónomo de investigación

El tercer programa atacó el cuello de botella más costoso del ciclo de diseño: el research. Antes, arrancar un proceso requería múltiples idas y vueltas para documentar el brief, y los hallazgos llegaban tarde. El agente — sobre M365 Copilot — rediseñó el flujo completo en tres momentos con niveles de madurez distintos.

Momento 01
Productivo
Pre-brief automatizado
El agente cruza datos disponibles desde Copilot y guía a quien realiza el proceso: le indica exactamente qué información necesita reunir para avanzar, sin idas y vueltas ni documentación faltante. El output es un Research Plan completo que le da autonomía real al product designer para arrancar sin depender del equipo de research.
Problema resuelto
Interminables idas y vueltas para completar un brief. Investigaciones que empezaban sin contexto suficiente.
Momento 02
Productivo
Insights en 72 horas
Post-entrevistas, el agente procesa las transcripciones e identifica patrones de comportamiento: recurrencias, tensiones, oportunidades. Entrega un adelanto de insights dentro de las primeras 72 horas, mientras el equipo de research completa el análisis formal. El reporte final es el mismo — pero auditado y enriquecido por las researchers.
Problema resuelto
Hallazgos que llegaban semanas tarde. Decisiones tomadas sin datos frescos del usuario.
Momento 03
Laboratorio
Usuarios sintéticos
Exploración activa de la posibilidad de generar perfiles de usuario sintéticos que complementen el research real — especialmente para escenarios donde reclutar usuarios es costoso o lleva tiempo. Sin resultados validados aún: es investigación en curso.
Hipótesis activa
¿Podemos acelerar ciclos de validación tempranos sin comprometer la calidad del insight?
El cambio de fondo
El product designer ya no espera al equipo de research para arrancar ni para aprender. El ciclo se cerró con más autonomía, más velocidad y el mismo rigor.
